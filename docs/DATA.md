# 資料與遷移

## RC 已選保存與恢復政策（2026-10-17）

本目標用新庫，沒有改動或遷移舊資料。schema 升至4以保存清除後的匯入阻擋；支援從4.6自己的1／2／3升級。舊程式不得打開schema4，回退必須使用升級前備份。下方schema3描述為該功能引入時的歷史。

原文、長期記憶與來源保留至明確刪除／清除／撤回；event的24小時只控制近期召回，不刪除原文。`storage.diagnostic_retention_days=30`自動清理 traces／usage（寫入時至多每小時一次），不清除 receipts／修訂／去重紀錄。這不會清理外部 log、備份或歷史評估產物；備份應另依管理流程處理。

清除會保留 guild／user／清除時刻／恢復同意這些最小阻擋欄位，不保留被清除文字。再次啟用新記憶不代表允許舊檔回灌。只有本人在已啟用伺服器執行 `/sayuki data_restore_import confirm:true` 才能放行管理匯入；指令沒有指定他人的參數，不會自動啟用記憶或執行匯入，現有 opt-out 仍生效。再次清除會撤銷前次恢復同意。無法由舊格式辨識的第三方間接提及仍非完整刪除保證。

Bot與apply匯入器共用 DatabaseLock：相同配置／實體路徑側檔，以及獨立的device/inode身分鎖。同一作業系統使用者即使以反向符號連結、跨目錄硬連結或不同TMPDIR啟動也涵蓋；身分鎖檔位於POSIX `/tmp/sayuki-database-locks-UID`、權限0700，不直接flock SQLite檔案。這是合作程序單例鎖，不防範其他程式刻意替換運行中的資料庫，也不是跨主機鎖。請仍停止Bot再匯入，不自行刪除持鎖中的側檔。Windows退路未實機驗證。

本節優先於下方早期交付中「保存／清除再匯入尚未決定」的歷史敘述。完整驗證狀態見 [RC 主交付](handoff/RC-COMPLETION.md)。

## 畫像的指定原文（2026-10-14）

已按使用者決策支援 `MEM_UPDATE: user_id | profile | key | value | msg_ID`。profile未填來源仍沿用當前訊息及其reply；指定來源時實際讀取那則原文，不以本輪請求替代。尾端msg_ID獨立解析，value內的一般管線字元仍保留；event的必填來源規則維持。

畫像的作者、時間、頻道和self_report／reported歸屬由實際來源決定。來源若是回覆，連同它自己的父訊息保存依據，不能混入本輪請求所回覆的另一則訊息。缺來源、缺父訊息、跨群組、未配置共享、不可讀、停用記憶或取消皆不寫入；讀取後重查存取與來源狀態。來源或父訊息刪改會撤回畫像，較早原文不得覆蓋較新的本人陳述。

這是來源契約修復，不是模型摘要的真實性證明；例如把暫時不在家寫入長期居住地仍可能過度概括。沒有自動整理此前綁錯來源的既有資料，也沒有改schema、到期／保存政策或角色卡。見[交付與限制](handoff/PROFILE-SOURCE-DELIVERY.md)。

## 自身日常與來源記憶（2026-10-05）

已按使用者決策接入：允許輕量日常RP，固定身分、年齡、外觀及基礎氣質由角色設定保留，其他偏好與有依據的對話經歷可累積。原角色卡沒有改寫；新增政策由 compiler 的第二則 system 組裝，沒有增加每回合前置模型。

新增自身條目分成 `preference`／`conversation`，存於原 `memories`，以 `self_memory_meta` 保存分類與1–4則明確來源ID；沿用 schema 3，開庫時附加建表。`memory_sources` 同時包含執行回合與指定來源，任一來源刪改、清除、作者停用或不可讀，條目就不帶入。使用者已選沿用配置共享頻道；同guild、當前Bot及所有來源都須可讀，沒有跨群組的全域公開。

`preference` 的 content 必須逐字引用 Bot 自己的簡短偏好原話（最多200字元），不能拿群友轉述、摘要、核心改寫或混入過去私生活的整句作偏好。關鍵詞驗證是保守護欄，可能拒絕合法表述，並非完整語意分類器。`conversation` 至少要 Bot 與另一作者各一則原文；content只供搜尋，模型收到原文、作者、時間與「只證明曾有對話」說明，不收到摘要作事實。即興私生活台詞不自動變成已核實活動；已完成工具操作經歷尚未另建分類。

```text
[[PERMANENT_MEMORY: preference | 我比較喜歡合作遊戲 | msg_100]]
[[PERMANENT_MEMORY: conversation | Minecraft車站討論 | msg_100,msg_101]]
[[EDIT_PERMANENT_MEMORY: self:1 | preference | 我更喜歡Minecraft | msg_220]]
[[DELETE_PERMANENT_MEMORY: self:1]]
```

舊單欄自由文字語法拒絕後可查 TOOL_HELP 修復；不猜舊key，也不靠一般 `MEM_UPDATE`／`MEM_OBSERVE` 改寫 Bot 自身。來源不明的舊條目不刪、不自動認證，載入標成 `legacy_unclassified`；匯入仍走既有行政入口。`MemoryService.self_memory()` 是保留的行政舊資料目錄，聊天編譯和搜尋走 `self_context()` 的有界、限範圍讀取。

預設 `memory.self_chars=2000`（完整JSON字元）、`self_limit=12`；最多掃500候選，超出帶 `scan_limited`。每則原文最多600字元、舊值最多600字元，縮短帶 truncated；預算或條數省略帶 omitted，不刪儲存內容、不把省略當成不存在。新舊條目可以並存；此批未新增偏好自動去矛盾、保留期限或完整自主生活系統。

驗收與如實保留的模型失敗見[自身記憶交付](handoff/SELF-MEMORY-DELIVERY.md)。核心無程式覆寫入口，不表示能保證每次模型台詞都符合角色；共享政策與資料護欄也不能代替 Discord 實測。

O6-D：events.attachments 的媒體項目可有 `kind=sticker`、sticker_id、format；沿用既有事件保存與失效範圍，schema 不變。貼圖描述為 executor 記憶體快取（最多128筆／5分鐘，到期按需清理），重啟消失；來源失效或記憶停用時不使用／新增該訊息的快取。圖片 observation 保存方式不變。

近期事件自動帶入由 `context/relevance.py` 按當前話題與可見直接 reply 做保守文字選取；未命中仍留庫，明確記憶搜尋可查回。穩定畫像保留既有修訂語意，事件的來源／共享／隱私／TTL 仍先經 MemoryService。見 [O4b-B 契約與限制](handoff/O4B-B-DELIVERY.md)。

## 近期事件以原文為依據（2026-10-02）

使用者已選定：event 的模型摘要只供檢索，回覆模型以來源原文判讀，不增加查核模型。`memories.key/value` 的儲存格式不變；event 的這兩欄作為內部索引，讀取時用 `events.text` 取代摘要正文，並保留真正來源作者、訊息 ID、發話時間與寫入時間。發話時間不是事件開始時間；subject_id 只是檢索對象，不能取代原文主詞的判斷。當時profile、自身永久記憶的政策未變；自身後續更新見本頁上方。

前景 `MEM_UPDATE` 的 event 寫入必須提供尾端 `source_id=msg_ID`，包括當前訊息；漏填或只把 ID 寫在摘要中會被拒絕，沒有寫入。profile 仍可用原本四欄，含管線符號的舊 profile 值維持解析相容。指定來源經既有 Discord 讀取與共享權限檢查，await 後再檢查權限、取消與隱私，然後走共用 writer。背景抽取仍用自身已核對的 source_id。

```text
[[MEM_UPDATE: 10 | event | Minecraft專案 | 專案近況的檢索詞 | msg_100]]
```

模型看到的 event key 改為 `event:資料列ID`，隱藏可能夾帶推測的索引標題。`MEM_DELETE` 或本頻道事件更正可使用這個 key，服務在原人物／伺服器／頻道內還原真正儲存 key；不開放跨範圍修改。資料列、舊索引及匯入檔沒有因此被刪除或重寫。

原文最多提供 2,000 字元，裁切時帶 `source_truncated`；仍受既有上下文總預算限制。缺少可核對原文的舊事件仍可透過索引搜尋命中，但 value 為空，標示 `source_available=false` 與需另查來源，不把舊摘要冒充原文。存在但範圍／作者不符或已刪除的來源不提供。原文失效、作者停用記憶的處理依來源 ID 生效。

TTL 沿用來源發話時間計算，不因晚些補寫重置時效。這不能自動修復以前綁錯來源的資料，也不保證模型必然選對來源／人物或正確解讀原文；只是讓摘要推測不再直接成為事件事實。背景記憶目前仍預設關閉。詳細實測見 [事件來源交付](handoff/EVENT-SOURCE-DELIVERY.md)。

新資料庫與舊版本分開。SQLite schema 目前為 alpha 基準 3；啟動時會將 4.6 自己的基準 1／2 資料庫以交易升級，保留條目 ID、來源與匯入標記。來源版本 4.0／4.5 的任意 SQLite 檔案不能直接指定成新版資料庫。升級後的檔案不能交給只支援基準 1／2 的程式；回退需使用升級前備份。

events保存觀測訊息；memories保存畫像、事件、自身和文化條目；summaries保存來源ID；receipts保存已嘗試發送及動作狀態；reminders保存到期工作；usage/traces用於診斷。自身條目維持跨回合保存，聊天載入已按上方分類、來源與共享範圍限制。

對話紀錄搜尋只涵蓋實際儲存內容（最多搜尋最近5000筆候選），不是完整Discord歷史搜尋。連結回傳時標示是索引，READ_MESSAGE才查證原文是否仍存在。不自動補抓一年前的全部頻道紀錄。

編輯或刪除訊息會移除舊來源衍生內容。一般畫像／事件查找需要guild與channel範圍；自動共享只接受明列頻道。來源時間與陳述者仍保留，舊資料不會被編造成有原文證據。

## 離線匯入

先停止目的端Bot。預設dry-run；不會修改來源，不會自動覆蓋衝突。V4沒有可靠範圍，所以必須明確指定guild/channel。自身永久記憶可用v4-self並指定Bot ID。

```sh
python scripts/import_memory.py /path/memory.json --format v4 --guild-id 123 --channel-id 456
python scripts/import_memory.py /path/memory.json --format v4 --guild-id 123 --channel-id 456 --destination data/sayuki.sqlite3 --apply
python scripts/import_memory.py /path/memory_v5.sqlite3 --format v5
```

目的資料庫會先在記憶中備份後合併；apply持有與Bot相同路徑的進程鎖。請仍保留目的原檔備份，不在運行中匯入。大型資料量的全量記憶備份方式尚需伺服器量測。

V5只映射有範圍、人物的可用事實和事件；情緒、關係分數、persona insight等未核定項目列入略過報告，不默認當成事實。記憶opt-out的項目略過。沒有scope、內容過大或衝突也會報告。尚未匯入V5全部provenance歷史、完整 conversation graph 關聯、文化無人物條目、提醒與統計；這些來源仍保留，不能聲稱已完成全部資料遷移。

已提供同伺服器範圍的使用者資料匯出、清除與停止記錄；不保證刪除他人文字中所有間接提及。自動保留期限尚未完成。現階段僅開發測試資料使用；正式切換前需完成既有資料政策與遷移驗收。

`observations` 儲存按需產生的圖片描述，來源修改、刪除或使用者清除會一起失效。`v5-events` 匯入模式可唯讀掃描舊版 chat_events，保留完整訊息 ID；不代表完整語意圖遷移。

背景 profile 需分類 basis 與可核對的原文片段：self_report 需本人來源；reported／inferred 分別保留轉述與推測。舊來源、轉述或推測不能覆蓋本人明確陳述。近況 TTL 從來源時間起算，不能靠重新抽取延長舊事有效期。

## 畫像更正與情境

`memories.context` 描述適用情境，空字串表示一般情境。profile 採追加版本，`profile_revisions` 記錄舊 ID 被新 ID 更正／撤回的關係；event、culture 保留原本更新方式；self 的分類、來源與編輯契約見本頁上方。

profile 的 active 只表示來源尚未失效／該版本未被撤回，不能單靠 active=1 判定目前有效版本；讀取一律經 MemoryService 解析修訂。匯出包含版本與可完整對應的修訂關係，匯入會辨認目前版本、撤回與批次重複，不把歷史內容重新當成新偏好。

`MEM_REVISE` 或背景抽取的 `target_id` 指向可讀條目。replace 沿用原 key 和情境；context 補充另一情境而不撤回原偏好；delete 追加撤回紀錄。背景模型負責辨認語意關係，服務負責檢查人物、來源順序、範圍和目前版本。不同名稱可經目標 ID 更正；沒有辨認出目標的同義 key 不會被全庫自動合併。同 key／同情境有不同內容且缺少更正關係時標為 conflict，不按時間任選一筆。

背景的 target_id 也可指向本頻道 event，轉為既有 key 的更新／撤回，例如退坑時撤回「最近每天玩」的近況。此入口檢查目標人物與頻道，不開放跨頻道原地修改 event；MEM_REVISE 工具仍只操作畫像。

讀取時只在當前可共享範圍套用更正。例如 A→B 的更正，A、B 可互讀時只提供 B 的新版本；不能共享 B 時，A 仍只讀到 A 的舊陳述。更正內容留在來源頻道，不複製進其他頻道。跨 A→B→C 的更正可沿鏈解析；修訂歷史不佔用 500 筆有效候選額度。刪除更正來源會清空其內容，但保留撤回關係，不在原本可共享的範圍自動復活舊偏好。使用者清除則刪除所有版本與關係。

摘要保存所有輸入依據的來源 ID，包含參考畫像與先前摘要的來源。讀取摘要也檢查共享、來源和隱私；任一依據不可讀就暫不提供摘要。更正會使依賴舊陳述的摘要失效；如果更正來自本次背景抽取，可立即保存同批已驗證的新摘要並保留前文依賴，不把自身更正誤判為外部競爭。其他頻道或沒有新摘要的情況則等後續批次重建。沒有可靠來源的匯入畫像仍可作背景，但參考它的背景批次不保存無法追溯的摘要。

背景批次採參與者可讀範圍的交集，模型回應後再檢查權限、來源、畫像版本與摘要版本。權限撤銷、資料清除或同時發生另一個更正時，過時結果會丟棄，交由既有重試排程處理；不在聊天前新增模型步驟。

## 長期印象的來源分類（schema 3）

`memories.basis` 區分 self_report／reported／inferred／unknown；`memory_sources` 保存最多八則依據，讀取要求全部來源仍可讀且作者未停用記憶。任一來源刪改或被清除會撤回衍生內容；直接 reply 確認同時依賴問句與確認訊息。舊條目保留值與 ID，分類為 unknown，不以作者相同就自動認證。

新低頻 `MEM_OBSERVE` 與既有 MEM_UPDATE／MEM_REVISE 共用寫入與修訂服務，不新增平行資料庫。印象不會因重複觀察自動成為本人事實；本人仍可依 ID 更正。詳見 [交付與限制](handoff/O4A-IMPRESSIONS-DELIVERY.md)。

背景工作從已存訊息恢復時保留 reply_to；短確認依賴被確認問句，若問句不在抽取批次內則不寫畫像。背景生成完成後，輸入近況／舊摘要若已到期就丟棄過時結果；不因資料列未修改而忽略自然到期。摘要文字之外另提供來源時間範圍給抽取模型，不代表已能逐句判斷時效。見 [O4b-A](handoff/O4B-A-DELIVERY.md)。

## O7-A 匯入契約與接入

匯入採固定欄位契約，未知欄位／自訂 id／缺欄位／錯型別／錯誤 ID 或時間逐筆列理由；一律 basis=unknown，active=0 的歷史不復活。V5 記憶檔的主體與來源作者 opt-out，以及目的端已停用者會被略過；來源頻道與記憶頻道不同不搬移範圍。v4-self 依主體＋key 去重，v5-events 同 ID 異範圍／作者列衝突。graph 與記憶來源庫可分離，不能假定單獨 graph 檔包含來源隱私資訊。

Codex 接入補上壞 kind 型別及目的端 WAL dry-run 保護，見 [O7-A 複核](handoff/O7-A-CODEX-REVIEW.md)。來源缺失事件保存多久、清除後再匯入、其他 Bot 訊息與未映射資料仍未定案；不因本批通過而開始正式遷移。

## MEMORY_SEARCH 原文來源鏈（M7）

正式搜尋命中後，在當前可讀頻道內沿同一 guild／channel 的 reply 父子關係補回原文。保留作者、時間、自身標記、reply、連結及本地索引狀態；reply 不自動等同更正、同意或同一人。根節點核對作者與文字前綴，額外來源排除已刪除、停用記憶、未來及當前回合訊息。

前8筆命中、2層、最多造訪24個ID；補充最多8則、4,000字元，單則超過1,800字元整則省略，並受現有工具總預算約束。省略數為下界；資料太滿可退回原搜尋結果。詳見[M7契約與限制](handoff/GROUP-MEMORY-M7-DELIVERY.md)。

## 初始上下文補全（M8）
